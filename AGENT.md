# AGENT.md

Guidance for AI coding agents (and contributors) working in this repository.

## Project overview

`slfrsk` is an R package and research compendium supporting a paninvasion
severity risk assessment for the spotted lanternfly (*Lycorma delicatula*),
a U.S. grape pest.

- Paper: Huron, N. A., Behm, J. E. & Helmus, M. R. 2022. "Paninvasion
  severity assessment of a U.S. grape pest to disrupt the global wine
  market." *Communications Biology*, 5:1–11.
  <https://doi.org/10.1038/s42003-022-03580-w>
- Research compendium / pkgdown site: <https://ieco-lab.github.io/slfrsk/>
- Associated large datasets (Dryad): <https://doi.org/10.5061/dryad.msbcc2g1b>
- Maintainer: M. Helmus (<mrhelmus@temple.edu>); lead author: N. Huron
  (<nahuron@gmail.com>)

The repository is 100% R and is structured as a standard R package that
also serves as a reproducible analysis pipeline for the paper above.

## Repository structure

- `R/` — package source functions (e.g. `extract_enm.R`, `extract_enm2.R`).
- `vignettes/` — the actual analysis pipeline, expressed as a series of
  numbered R Markdown vignettes (see "Vignette pipeline order" below),
  plus generated output figures (PDFs) and `references.bib`.
- `data/` — packaged (processed) datasets shipped with the package
  (`LazyData: true`).
- `data-raw/` — scripts used to prepare/generate the datasets in `data/`.
- `man/` — Rd documentation generated by roxygen2. Do not hand-edit.
- `docs/` — pkgdown-built site output. Do not hand-edit.
- `sandbox/` — exploratory/scratch scripts not part of the polished,
  reproducible pipeline. Treat with caution; don't assume code here is
  maintained or correct.
- `DESCRIPTION` / `NAMESPACE` — package metadata, dependencies
  (Imports/Suggests/Remotes), and exported symbols. `NAMESPACE` is
  generated by roxygen2; do not hand-edit.
- `README.Rmd` / `README.md` — `README.md` is generated from `README.Rmd`.
  Always edit `README.Rmd` and re-knit; never edit `README.md` directly.

## Vignette pipeline order

Vignette filenames use numeric prefixes that indicate their intended
execution order in the analysis pipeline:

1. `vignette-001-overview.Rmd`
2. `vignette-002-terms.Rmd`
3. `vignette-003-get-gbif-data.Rmd`
4. `vignette-010-tidy-data.Rmd`
5. `vignette-011-suitability-models.Rmd`
6. `vignette-021-quadrant-plots.Rmd`,
   `vignette-026-quadrant-plots-alt-median.Rmd`,
   `vignette-027-quadrant-plots-alt-mean.Rmd`
7. `vignette-030-potentials-maps.Rmd`
8. `vignette-040-ee-data.Rmd`
9. `vignette-041-market-plot.Rmd`
10. `vignette-042-trade-presence.Rmd`
11. `vignette-050-ava-temp.Rmd`
12. `vignette-060-spread-figure.Rmd`

When adding a new analysis step, follow this numbering convention (leave
gaps for insertions, e.g. add `vignette-012-...` between 011 and 021) and
place it at the appropriate point in the pipeline rather than appending it
at the end regardless of content.

## Build, check, and documentation conventions

- Install from GitHub: `devtools::install_github("ieco-lab/slfrsk")`.
- Regenerate documentation/`NAMESPACE` after changing roxygen comments:
  `devtools::document()` (RoxygenNote 7.1.1).
- Run package checks with `devtools::check()` before proposing changes
  that touch `R/`, `DESCRIPTION`, or `NAMESPACE`.
- Vignettes are built with `knitr` (`VignetteBuilder: knitr`).
- Dependencies are declared in `DESCRIPTION` (`Imports`, `Suggests`), not
  a lockfile. Two dependencies are GitHub-only and listed under
  `Remotes:` (`ropensci/scrubr`, `jasonleebrown/humboldt`) — install these
  from GitHub, not CRAN.

## Coding conventions

- R code generally follows tidyverse conventions (`dplyr`, pipes,
  `ggplot2` for figures, `here` for paths).
- Keep large generated binary outputs (PDF figures, rasters, `.doc`
  files) out of manual edits; regenerate them from the corresponding
  vignette instead of editing in place.
- Check `.gitignore` and `.Rbuildignore` before adding new large data or
  build artifacts to avoid bloating the repository.

## Things to avoid

- Do not hand-edit generated files: `README.md`, `man/*.Rd`, `NAMESPACE`.
- Do not treat `sandbox/` scripts as part of the supported, reproducible
  pipeline.
- Do not commit large raw geospatial/raster datasets directly; prefer
  referencing the Dryad-hosted datasets and documenting how to fetch them
  in `data-raw/`.
